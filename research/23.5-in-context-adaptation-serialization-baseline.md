# 23.5 — In-context adaptation serialization baseline

(`chat-export-1785143922754.json`, Qwen3.8-Max-Preview). Not yet

## Source and evidence boundary

This entry arises from the thesis reframe documented in
`notes/2026-07-26_in-context_serialization_thesis_reframe.md`. The reframe
collapses the Oczy question from "can a system learn?" to "can the result of
in-context learning be serialized into a compact persistent representation
that, when re-injected next session, reproduces the adaptation?" This entry
is the baseline test of that question. It does not require meta-training, a
cortex, or the full R20 pipeline. It is the cheapest possible test of whether
the serialization approach is viable.

Related work: context distillation (Snell et al. 2022, arXiv:2209.15189),
persistent KV cache (LMCache, MemArt), ILCP (Banerjee & Awan 2026), TTT-E2E
(Tandon et al. 2025), harness-level serialization (Karten et al. 2026,
arXiv:2605.09998 — see Addendum below). See
`notes/2026-07-26_in_context_serialization_literature.md` for the full
landscape. Context distillation proves in-context learning can be serialized
into weights but violates the frozen-organ constraint. KV cache persistence
proves it can be saved but is bulky and uncompressed. Nobody has published a
benchmark showing that a compact learned latent can preserve the behavioral
adaptation of in-context learning in an LLM across sessions. This entry is
that benchmark.

## Problem

The reframed thesis asks: can the in-context adaptation of a frozen LLM be
compressed into a persistent latent state that survives sessions and
recapitulates the behavioral shift without the original context? Before
building a meta-trained cortex to do the compression (R24–R30), we need to
know whether the compression is possible at all — even with simple, non-meta-
learned methods.

If even a large soft prompt cannot recover the in-context behavioral shift,
the entire serialization approach is dead and R24–R30 are unnecessary. If a
small one can, we have a product.

## Hypothesis

**H-SERIALIZE-BASELINE:** a learned soft prompt (or single latent vector
injected at a chosen layer), trained on a few in-context examples of a
user pattern, can recover a measurable fraction of the frozen LLM's
in-context behavioral shift on held-out probes, without the original context
being present at evaluation time.

## Method

Take the frozen LLM (`Qwen/Qwen2.5-0.5B-Instruct`, the pinned organ). For a
set of user patterns (e.g., date formatting, abbreviation expansion, tone
adjustment):

1. **Measure the in-context shift.** Give the model 3 examples of a user
   pattern in the context. Measure accuracy on held-out probes from that
   pattern. Call this `acc_with_context`.
2. **Measure the baseline.** Evaluate the same probes with no context. Call
   this `acc_no_context`. The in-context shift is
   `acc_with_context - acc_no_context`.
3. **Re-inject the raw examples as a prefix** → measure recovery. This should
   be ~100% of the shift (it is just in-context learning again, with the
   examples re-added). Call this `acc_raw_prefix`.
4. **Re-inject a text-level harness serialization** (ADDENDUM 2026-07-26) →
   a small Refiner-built bundle (rewritten prompt + few skills + memory
   entries) produced from the same 3-example trajectory, then re-injected as
   text at evaluation. Call this `acc_text_harness`. This is the structured
   text-level version of the "save button": Karten et al. (arXiv:2605.09998)
   report it recovers a majority of the gap between a minimalist baseline and
   a hand-engineered expert harness on a long-horizon embodied task. It is
   the lossy-*text* point on the compression curve that a compact latent must
   beat on tokens/bytes.
5. **Re-inject a learned soft prompt** (prefix tuning, trained on the 3
   examples via gradient descent on the soft prompt only, organ frozen) →
   measure recovery. Call this `acc_soft_prompt`.
6. **Re-inject a single latent vector injected at layer L** (trained the same
   way, organ frozen) → measure recovery. Call this `acc_latent_vector`.
7. **Re-inject nothing** → measure recovery. This should be ~0% (same as
   `acc_no_context`). Call this `acc_nothing`.

Plot recovery ratio (`acc_X - acc_no_context`) / (`acc_with_context -
acc_no_context`) vs. representation size (tokens for text/harness/prefix,
dimensions for soft prompt / latent vector). This curve **is** the
feasibility result, and the harness-serialization point anchors the
lossless-ish end that the compact latent must undercut on size.

### Controls

- The organ is frozen for all conditions except the raw-prefix control (which
  is just in-context learning, no training).
- Soft prompt and latent vector training uses only the 3 examples, not the
  held-out probes.
- Multiple user patterns, multiple seeds per pattern.
- The latent vector injection layer L is swept (e.g., layers 4, 12, 20, 24
  for Qwen-0.5B's 24 layers).

## Success criterion

`acc_soft_prompt` or `acc_latent_vector` recovers ≥ 30% of the in-context
shift (`acc_with_context - acc_no_context`) on at least one user pattern and
one injection layer. This is a low bar — it just asks whether there is any
signal to compress.

## Kill criterion

If neither `acc_soft_prompt` nor `acc_latent_vector` recovers any measurable
fraction of the in-context shift across all user patterns, layers, and seeds,
the serialization approach is dead. The in-context adaptation cannot be
compressed into a compact persistent representation. R24–R30 are unnecessary.
Write up the negative result.

## Cost

Cheap. No meta-training, no cortex, no 90-shard calibration. Just:
- Forward passes on the frozen organ with and without context.
- Soft prompt / latent vector training on 3 examples per pattern (minutes per
  pattern on CPU).
- A few user patterns × a few layers × a few seeds.

One afternoon. CPU or single small GPU.

## Why this is first

This entry answers the question every other entry in R24–R30 depends on: *is
there a signal to compress?* If the in-context shift cannot be recovered by
any compact representation, no amount of meta-training or architectural
refinement will help. If it can, the recovery curve tells you which
representation format (soft prompt vs. latent vector, which layer) is most
promising, and R24–R30 can be designed around that.

## Relationship to existing evidence

The Oczy evidence ledger already contains related results:
- R02 (KV-slot fact injection): showed KV content can reproduce prefix
  behavior but cannot force arbitrary token binding.
- R09 (HF KV-slot): reached 1/3 absolute recall.
- R19 (latent articulation): blocked at the DEV articulation gate.

Under the old framing these were "failures to control the organ." Under the
reframed thesis they are "early attempts at the save button." This entry
re-tests the core question with the right framing and the right metric
(recovery ratio, not absolute recall).

## Addendum 2026-07-26 (from Continual Harness, arXiv:2605.09998)

This addendum adds the **text-level harness-serialization condition** (Method
step 4) to this draft. Rationale and provenance:

- Karten et al. (arXiv:2605.09998) formalize "Continual Harness": a refiner
  (the same model as the actor) reads the recent trajectory and applies CRUD
  edits to harness state H = (system prompt, sub-agents, skills, memory)
  mid-episode, reset-free. H **is** a text-level serialization of in-context
  adaptation, and the paper demonstrates it recovers a *majority* of the gap
  between a minimalist baseline and a hand-engineered expert harness on
  Pokémon Red/Emerald (seed medians, per-seed traces reported).
- The July-26 reframe maps retrieval-vs-metabolism onto lossless-vs-lossy
  compression. In that frame the paper's harness state is the **lossy-text**
  point: more compact than raw context / persistent KV, far larger than a
  compact latent, and proven to work at scale. R23.5 must therefore report
  the latent against **two** anchors — raw re-injection (~lossless) and
  text-level harness serialization (lossy-text). A compression-ratio claim
  without the harness point would be unanchored.
- Two further paper results port directly here:
  (a) **bootstrap frozen vs. bootstrap updating** — an inherited
  serialization accelerates even when task state resets, and continued
  refinement adds on top; that is exactly R23.5's serialize→restore→continue
  test and should be added as a secondary analysis when this entry is
  authorized.
  (b) **capability floor** — harness/refinement gains are capability-dependent
  and vanish below a floor. With Qwen-0.5B as the organ, a weak or null
  `acc_text_harness` may reflect the organ floor, not the serialization idea;
  any negative write-up must state this framing (see S4.3 / R20 organ-ceiling
  notes).

On human authorization of this draft, fold step 4 and the bootstrap analysis
into Method and Success criterion. Nothing here modifies eval/v2 or any
approved threshold.
