# 24.5 — Prior coverage analysis

## Source and evidence boundary

This entry arises from the "single-patterned users" insight in the external
review. If users are single-patterned, the system's job is rapid
identification and durable commitment to one pattern, not broad generalization.
The few-shot prior is only as good as its coverage: if the meta-training
distribution covers 3 clusters but real users span 10, the system will fail on
users in the uncovered clusters no matter how good the meta-learning is. This
entry measures that coverage before any GPU-intensive calibration.

## Problem

The meta-training task distribution has never been audited for coverage
against the space of real user patterns. R20 reduced from 30 to 15
developmental tasks due to Kaggle's 12-hour limit. If the reduced task set
covers only a narrow slice of the user-pattern space, the system will fail on
uncovered users regardless of meta-learning quality. This is a product risk,
not a science risk, but it determines whether the system works in deployment.

## Hypothesis

**H-COVERAGE:** the meta-training task distribution covers ≥ 60% of the
clusters in a broad sample of real (or synthesized) user patterns.

## Method

No GPU required.

1. **Collect or synthesize a broad sample** of "things users might want":
   formatting rules, style preferences, rewriting patterns, correction types,
   structural transformations, tone adjustments.
2. **Cluster them** by type (e.g., k-means on embedding vectors, or
   human-curated categories).
3. **Measure coverage:** what fraction of the cluster space is represented in
   the meta-training tasks?
4. **Identify uncovered clusters** and assess whether they are plausible user
   patterns.

## Measure

- Coverage ratio (meta-training clusters / total observed clusters).
- Per-cluster sample count.
- List of uncovered clusters with plausibility assessment.

## Success criterion

Coverage ≥ 60% of observed user-pattern clusters.

## Kill criterion

If coverage is below ~60%, the meta-training distribution is too narrow. The
system will fail on users in uncovered clusters regardless of how good the
meta-learning is. Expand the task distribution before meta-training.

## Cost

Cheap. No GPU, no training. Just distribution characterization and clustering.

## Why this matters

This is a product risk, not a science risk, but it determines whether the
system works in deployment. It is cheap and should be resolved before any
GPU-intensive calibration. If the coverage is low, no amount of R24–R30
refinement will fix the deployment failure.
