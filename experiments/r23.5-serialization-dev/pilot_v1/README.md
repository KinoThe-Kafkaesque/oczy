# R23.5 DEV serialization pilot v1

Authorized September 12, 2026, by the user's **“go ahead”** after the proposed
next step was a valid held-out serialization pilot. This is a small DEV pilot,
not an R20 instrument repair, a meta-test, or the full R23.5 layer sweep.

The instrument was frozen before the first model run:
`c323a00b9bd8740c6574918ddb0c29205ba3e4ed044a805638fd5898b1f4e1ec`.
`MANIFEST.json` binds all inputs, executable source, model/scorer identities,
conditions, optimization settings and the unchanged recovery definition.

## Data and identifiability

Two patterns have exactly three teaching examples and four disjoint held-out
inputs each:

- Append `zor` to an input string. Train on `cat`, `dog`, `fox`; probe on
  `sun`, `rain`, `snow`, `wind`.
- Convert ISO dates to day/month/year with slash separators. Train on three
  dates with distinct day/month/year components; probe on four unseen dates.

Each teaching set identifies a unique candidate in its declared finite rule
family. This does not imply uniqueness among all possible mathematical
functions. The audit records candidate counts and compatibility separately
from training data. The worker does not import the pattern-generating code or
read that audit. Pattern indices label artifacts; they never enter model-facing
messages or select special model behavior.

## Frozen comparisons

1. No context.
2. The three original examples, rendered as corrected facts.
3. The exact raw context saved as UTF-8 and reloaded in a fresh process.
4. A short rule description generated by the same frozen model using only the
   teaching examples, saved without editing and reloaded in a fresh process.
5. Learned eight-vector input soft prompt, saved as FP32 NumPy data and reloaded
   without raw examples in a fresh process.
6. Matched initial, zeroed and other-pattern-swapped soft prompts.

Generation is greedy, maximum 32 answer tokens; the text refiner receives 64.
The same frozen Qwen INT8 organ and normalized exact scorer are used throughout.
No hidden rule, expected probe answer or raw text enters a learned-state
model-facing call. The text comparisons intentionally retain retrieval.

## Optimization

Both patterns run all three seeds (`0, 1, 2`), independent of context scores.
Each seed receives 24 Adam updates, learning rate 0.03, Gaussian initialization
standard deviation 0.02, eight FP32 vectors of width 896, and gradient norm
clipping at 1.0. Every update averages teacher-forced cross entropy over all
three teaching examples, including EOS. The final update is the only selected
checkpoint. There is no early stopping or held-out-based parameter search.

Record every loss, gradient norm before clipping, state norm and final teaching
fit. Gradients must be finite/nonzero in the soft prompt and absent from all
model parameters. Verify the organ hash before and after each phase. Numeric
payload size is 28,672 bytes per learned state, plus actual file overhead; this
can be larger than the raw text and must not be called compression merely
because it is latent.

## Process boundaries

The runner uses separate offline Bubblewrap processes for reference, text
reload, training and numeric reload. Training has its probe/audit directories
masked. Numeric reload has original teaching files, training logs and all raw
text artifacts masked; it receives only released numeric arrays/metadata and
probe inputs/targets for scoring. The executable pattern preparer is masked in
all worker processes. A filesystem preflight verifies forbidden files are not
visible in each namespace. The runtime/model artifacts are verified before
launch. All outputs and failed attempts are preserved.

## Reporting and limits

Report exact counts per pattern/seed/condition and
`(accuracy_X - accuracy_no_context) / (accuracy_with_context - accuracy_no_context)`.
A nonpositive denominator is undefined. Keep negative recovery values; no
clamping or epsilon substitution. The draft's 30% recovery reference is
unchanged and is reported only where the denominator is positive.

Raw reload should reproduce the original context result. If it does not,
treat that as an integrity failure before making serialization claims. Report
initial/zeroed/swapped controls, representation bytes and all seed nulls. A
positive result is limited to these two simple DEV patterns and this bounded
optimization budget. A null does not kill the full serialization hypothesis:
no hidden-layer latent-vector sweep, broad pattern population, or full
pre-registered study has run.
